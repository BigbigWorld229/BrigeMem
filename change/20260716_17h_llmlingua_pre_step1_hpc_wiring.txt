一、修改文件

1. hpc/memweave-qwen25-locomo.sh

二、修改的函数及代码位置

1. 新增 shell 函数 append_llmlingua_args()
   - 函数直接接收 ablation_config.json 中
     components.llmlingua_pre_step1_compression 的 true/false 值。
   - true：要求 LLMLINGUA_MODEL_DIR 非空且目录存在，然后向 Python 入口参数数组追加
     --enable-precompress、--llmlingua-model-dir、--llmlingua-device、
     --llmlingua-rate、--llmlingua-target-token 和 --llmlingua-min-tokens。
   - false：不追加任何 LLMLingua 参数，因此 Python 入口的 enable_precompress 保持 False，
     Step 1 使用未压缩原文。
   - 非 true/false 值返回状态码 2，避免无效配置被静默接受。

2. 脚本顶层消融配置解析与启动参数组装
   - 将解析值保存为 LLMLINGUA_PRE_STEP1_COMPRESSION，并用 case 严格映射到现有
     PRECOMPRESS=1/0；该变量继续控制 precompress/plain 运行目录命名。
   - 在启动 vLLM 前构造 EXTRA_ARGS 并调用 append_llmlingua_args()，使配置或模型目录
     有误时能够提前失败，不占用已启动的模型服务。
   - 删除原有“启用但模型目录为空时静默退回原文”的分支，保证配置为 true 时确实启用
     LLMLingua，配置为 false 时确实不启用。
   - 常规日志直接打印 true/false；HPC_RUNTIME 调试日志新增
     llmlingua_pre_step1_compression=<true|false>，便于核对实际消融状态。

2. ablation_config.py 解析默认 ablation_config.json：通过，输出

3. append_llmlingua_args() 双分支测试：
   - true 时参数数组包含 --enable-precompress 和完整 LLMLingua 参数；
   - false 时参数数组为空，不包含压缩开关。

   - true 得到 PRECOMPRESS=1、RUN_VARIANT=precompress，并包含 --enable-precompress；
   - false 得到 PRECOMPRESS=0、RUN_VARIANT=plain，并且不包含 --enable-precompress。
